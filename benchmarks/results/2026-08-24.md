# Benchmark results - 2026-08-24

Ran on my laptop with an AMD Ryzen 7 7730U on Linux x86-64 using Rust 1.97.1
from my devshell. Criterion ran on CPU 2 with a 1 second warm-up, 2 second
measurement window, and 20 samples. Values below are the estimated means from
one uninterrupted run. You might get slightly different results on different
hardware but the trends should remain the same.

> [!NOTE]
> The previous recording was taken on a Ryzen 7 7700X desktop. Absolute times
> here are lower due to the difference in hardware, so compare against the
> desktop numbers with that in mind.

> [!IMPORTANT]
> The shared operation is complete lossless syntax parsing. Nixon's stricter
> default entry point performs additional Nix parse-time validation and is not
> used in this table.

The `nix-instantiate` column is the reference C++ parser (Lix 2.95.3) spawned as
a subprocess (`nix-instantiate --parse -`) with input piped through stdin. Its
timing includes process startup, which is a roughly 49 ms floor that dominates
the three smallest inputs; only `large` spends a meaningful share of its time
actually parsing. `--parse` also checks for unbound variables, which the other
adapters do not, so treat the smaller rows as a lower bound on Nixon's
advantage.

## Stripped native artifacts

Built from the same comparison package with fat LTO and one codegen unit.

| Adapter         |     Bytes |
| --------------- | --------: |
| Nixon           |   357,072 |
| rnix            |   389,840 |
| NixEL           |   561,888 |
| nix-instantiate | 4,502,920 |

The comparison is a little unfair for `nix-instantiate` since `nix-instantiate`
is actually a symlink into Lix's single multi-call `nix` binary, so its size
covers the whole command set and not just the parser, but it has been recorded
here for archival reasons.

## Peak heap while parsing `large`

Massif 3.27.1 measured one parse in each isolated adapter. Input generation is
included but file I/O isn't.

| Adapter         | Peak heap bytes |
| --------------- | --------------: |
| Nixon           |       2,710,549 |
| rnix            |       4,262,041 |
| NixEL           |      14,675,107 |
| nix-instantiate |      10,626,638 |

Nixon's retained syntax record is 15 bytes per node or token. Parser events and
tree records are allocated in fixed chunks, allowing completed event chunks to
be released while the output is built.
